## 1. 文档定位

本文档回答三个问题：

1. **有哪些页面** —— 页面清单与路由；
2. **每个页面长什么样** —— 区块顺序、组件、内容来源；
3. **每个页面在什么状态下表现如何** —— 加载 / 空 / 错误 / 无结果，以及响应式与无障碍要求。

设计令牌与组件视觉细节不在本文档重复，统一以 `DESIGN_SYSTEM.md` 为准。

## 2. 全局页面规则

### 2.1 容器与栅格

| 容器 | 最大宽度 | 用途 |
|---|---|---|
| `container-page` | `1200px` | 全站默认容器，左右内边距 `16 → 24 → 40px` |
| `container-prose` | `720px` | 长文正文（约 `68ch`，保证可读性） |
| 全宽区块 | 100% | 仅用于背景色带与分隔线，内容仍受 `container-page` 约束 |

- 栅格：12 列，间距统一用 `gap`，禁止给单个子项加 `margin`；
- 组件内部响应式优先使用**容器查询**，页面级才用媒体查询。

### 2.2 垂直节奏

| 位置 | 移动端 | 桌面端 |
|---|---|---|
| 区块之间（`.section`） | `48px` | `96px` |
| 页面头部（PageHero）内边距 | `40px` | `56px` |
| 标题到正文 | `16px` | `16px` |
| 列表项之间 | `20px`（配发丝分隔线） | `20px` |

### 2.3 标题层级（全站强制）

- 每页**有且仅有一个 `<h1>`**：
  - **首页**：由**报头院名**承担（`<h1 class="brand-cn">`），与 `cas.cn` 等机构门户一致；
  - **内页**：由 `PageHero` 承担，此时报头院名降级为 `<span>`，避免同页出现两个 `h1`；
- 区块标题为 `<h2>`，区块内小标题为 `<h3>`，**不得跳级**；
- 首页取消大字号 Hero 后，**机构定位条是普通段落，不承担 `h1`**（此处易漏，改版时须回归检查）；
- 卡片、列表项标题使用 `<h3>`，不得为了视觉大小而升级为 `<h2>`。

### 2.4 吸顶导航与偏移（原「固定导航补偿」已废弃）

报头改为**报头随页滚动 + 主导航吸顶**，不再整体固定：

| 层 | 高度令牌 | 值 |
|---|---|---|
| 顶部工具条 | `--utility-h` | `34px`（`<640px` 隐藏） |
| 报头 | `--masthead-h` | `84 / 64 / 60px` |
| 主导航（吸顶） | `--nav-h` | `52 / 48 / 44px` |

- **`body` 不再设置 `padding-top`**，页面内也不得叠加额外顶部间距；
- 锚点跳转由全局 `scroll-margin-top: calc(var(--nav-h) + 1.5rem)` 统一处理，页面级不要重复设置；
- 吸顶侧栏（右信息栏、目录）统一用 `lg:top-[calc(var(--nav-h) + 1.5rem)]`；
- **实现约束（重要）**：`.nav-wrap` 必须是 `<body>` 的直接子元素，即**放在 `<header>` 之外**。sticky 只在父级包含块内生效，若留在 `<header>` 内，滚过报头后导航会随报头一同滚走，吸顶失效。

### 2.5 页面骨架（所有页面共享）

```text
Skip Link（聚焦时可见）
header.site-header（静态，随页滚走）
  ├─ 顶部工具条（中文 / EN、全站搜索、内容发布后台）
  └─ 报头（院徽 + 中英文院名 + 站内搜索表单 + 快捷入口）
div.nav-wrap（sticky top:0，<header> 之外的兄弟节点）
  ├─ 主导航（首页 / 机构 / 研究 / 成果与动态 / 加入我们）
  ├─ 移动端汉堡 + 搜索按钮
  └─ Mega Menu 面板（按需展开）
main#main
  ├─ PageHero（页面头部：面包屑 / 眉标 / h1 / 描述）
  └─ 页面内容区块…（列表页为「主内容 + 右信息栏」）
footer
  ├─ 友情链接条
  ├─ 多列导航 + 联系
  └─ 深底备案条
浮层（互斥，同一时刻只允许一个）
  ├─ Mega Menu
  ├─ 移动端 Drawer
  └─ 搜索弹层
```

**浮层关闭顺序（`Esc`）**：搜索弹层 → 移动抽屉 → Mega Menu。关闭后焦点必须归还触发控件。

### 2.6 客户端脚本与 View Transitions（全站强制）

站点在 `BaseLayout` 中启用了 `<ClientRouter />`：站内跳转是**客户端换页**，`<body>` 内 DOM 会被整体替换，而**模块脚本在整个会话内只执行一次**。凡是在模块顶层缓存 DOM 节点并直接绑定监听的脚本，换页后必然失效（典型症状：换页后 Mega Menu、抽屉、搜索全部点不动）。

任何 `<script>` 都必须遵守：

1. **元素查询写在函数内**，换页后重新取；顶层只允许保留与 DOM 无关的状态（搜索索引、防抖句柄、焦点记忆）；
2. **初始化由 `astro:page-load` 驱动**（首次加载与每次换页都会触发），并在函数末尾立即调用一次；
3. **绑定要幂等**：给已绑定节点打 `data-hb="1"` 标记，重复调用不产生重复监听；
4. **`document` 级监听**（如全局快捷键）只注册一次，用一个标记位守卫。

```js
function init() {
  // 每次换页后重新查询，重置与页面绑定的状态
  const btn = document.querySelector('[data-x]');
  if (btn && btn.dataset.hb !== '1') {
    btn.dataset.hb = '1';
    btn.addEventListener('click', handler);
  }
}
const root = document;
if (!root.__inited) {
  root.__inited = true;
  document.addEventListener('astro:page-load', init);
}
init();
```

**悬停与点击的顺序陷阱**：桌面端 `mouseenter` 先于 `click` 触发。若 `click` 一律做「打开/关闭」切换，用户鼠标移入打开面板后再点击就会被立刻关掉，表现为「点不开」。Mega Menu 用 `openedByClick` 区分来源：悬停/聚焦打开时不切换，只有「由点击打开」后的再次点击才关闭。

### 2.7 眉标签语义（全站统一）

眉标签（`PageHero.eyebrow`）**只表示内容类型**，取值来自 `src/data/site.ts` 的 `sectionEyebrow`。

学术站点的读者需要一眼判断「这是什么类型的学术产出」。此前同一个视觉位置承载了 6 种互不相干的语义
（内容标签 / 资助来源 / 英文名 / 序号 / 页面名），同类内容在不同页面读起来像不同的东西。

| 页面 | 眉标签 | 依据 |
|---|---|---|
| 成果详情 | 文献类型（期刊论文 / 会议论文 / 著作 / 报告） | `publicationTypeLabels` |
| 活动详情 | 活动类型（学术讲座 / 研讨会 / 工作坊 / 学术会议） | `eventTypeLabels` |
| 新闻 / 公告 / 项目 / 成员 / 方向 / 专题详情 | `sectionEyebrow.<collection>` | 内容类型名 |

**禁止**：用 `序号`（`方向 01`）、`资助来源`、`英文名`、或内容标签（首个 tag）充当眉标签。
序号还违反设计品位门禁 `TASTE-002`（编号式标签）—— 该规则**只在眉标签元素内部**匹配编号，
不会误伤正文里的数字。

## 4. 逐页规范

### 4.1 首页 `/`

**目标**：10 秒内让访客判断「这是什么机构、研究什么」。

改为**机构门户式高密度分区**（参照 `cas.cn`）。机构身份由报头承载，因此首页不再放大字 Hero。

| 序 | 区块 | 内容 | 组件 | 备注 |
|---|---|---|---|---|
| 1 | 机构定位条 | 一句话定位 + 四方向概览 | 原生 | 单条紧凑带，背景 `surface` |
| 2 | 焦点图区 | 左：**焦点轮播**（焦点优先 + 最新要闻，共 5 条）；右：通知公告 6 条 | `Carousel` + `AbstractFigure` + `NoticeList` | 桌面 `1.5fr : 1fr` |
| 3 | 要闻 | 3 张新闻卡（配图 + 日期 + 标题 + 摘要） | `portal-card` + `AbstractFigure` | 摘要 `line-clamp-3` |
| 4 | 学术活动 \| 科研项目 | 左：活动 4 场；右：在研项目要点列表 | `EventItem` / `brief-list` | 桌面双栏 `1fr 1fr` |
| 5 | 研究方向 | 4 张方向卡（配图 + 编号 + 标题 + 一句话） | `portal-card` + `AbstractFigure` | 按 `order` 排序 |
| 6 | 学术成果 | 最近 5 条，按引用格式 | `PublicationItem` | 年份倒序 |
| 7 | 研究团队 | 4 位成员 | `PersonCard` | 按 `order` 排序 |
| 8 | 数据统计带 | 成立年份 / 方向 / 成果 / 人员 | `.stat-band` | 深底，数字等宽 |
| 9 | 专题专栏 | 3 张专题卡（配图） | `portal-card` + `AbstractFigure` | 数据源 `src/data/topics.ts` |
| 10 | 加入我们 | 主张 + 两个动作 | 原生 + `.btn` | 描边区块 |

**配图规则**：卡片配图统一走 `CoverImage`（见 `DESIGN_SYSTEM.md` §3）：

1. **优先用真实封面**——条目 frontmatter 里填了 `cover`（形如 `/images/foo.png`）就渲染真实图片，并取 `coverAlt` 作为 `alt`（没填就用条目标题）；
2. **没有 `cover` 才回落** `AbstractFigure`（按 `seed` 确定性生成 SVG，`aria-hidden`）。`seed` 用条目 `id` 或专题 slug，保证每次构建一致；
3. 真实图片必须 `object-cover` + 显式 `h-full w-full`，否则会撑破 `.figure-frame`；首屏（轮播第 1 张）用 `loading="eager"`，其余 `lazy`。

**可用 `cover` 的集合**：`news`、`research`（均有 `cover` + `coverAlt`）；专题 `src/data/topics.ts` 用可选的 `image`。图片经后台上传到 `public/images/`，**上传后需点「发布站点」重新构建**才会生效。

**响应式**：焦点图区在 `<1024px` 收为单栏；卡片网格 `1 → 2 → 3/4` 列递进；统计带保持两列。
**SEO**：`h1` 由报头承载的机构名语义提供；`ResearchOrganization` 结构化数据在 `BaseLayout` 注入。
**约束**：区块标题统一用 `SectionHeading`（左竖线 + 中英标题 + 「更多 +」）；卡片使用 `portal-card`，**禁止卡片嵌套卡片**。

#### 焦点轮播（`src/components/ui/Carousel.astro`）

| 项 | 规范 |
|---|---|
| 数据来源 | `news` 集合：`featured` 优先，其余按日期倒序补足，共 **5 条** |
| 切换方式 | 左右箭头、圆点指示器、`←` / `→` 方向键；自动播放 **5.5s** 一张，循环 |
| 暂停条件 | 鼠标悬停、键盘聚焦（`:focus-visible`）、`prefers-reduced-motion: reduce`、页面不可见（`document.hidden`） |
| 手动控制 | 提供暂停/继续按钮（WCAG 2.2.2 要求可暂停的自动播放） |
| 标题层级 | slide 标题一律 **`h2`**——首页 `h1` 在报头，轮播里出现 `h1` 会破坏全站唯一 h1 审计 |
| 无 JS 降级 | 第一张无 `hidden`、其余带 `hidden`，控件默认 `display:none`；脚本就绪后加 `data-ready="true"` 才切换到堆叠淡入淡出 |
| 无障碍 | 容器 `aria-roledescription="carousel"`；slide `role="group"` + `aria-label="2 / 5"`；视口 `aria-live="polite"`；当前圆点 `aria-current="true"` |
| 高度稳定 | 所有 slide 叠在同一网格格（`grid-area: 1/1`），容器高度取最高一张，切换不跳高 |

**实现陷阱（已踩过）**：`initCarousel()` 在首次加载会执行**两次**（末尾手动调用 + `astro:page-load` 触发）。若每次 init 都清空全部定时器，第二次会清掉第一次建的定时器，又因 `data-hb` 幂等标记提前 `return` 而不重建，结果**自动播放永远不动**。正确做法是用 `Map<HTMLElement, number>` 记录每个 root 的定时器，**只在 root 已脱离文档（`!el.isConnected`，即换页后旧 DOM）时才清理**。

**学术检索元数据（`src/lib/citation.ts` → `SeoHead.astro`）**：

成果详情页输出 Highwire Press `citation_*` 标签，这是 Google Scholar 一类学术检索系统抓取元数据的依据。
没有它，成果页在常规搜索引擎里能搜到，但在学术检索链路里是**隐形的**。

| 标签 | 来源 | 注意 |
|---|---|---|
| `citation_title` | `title` | |
| `citation_author` | `authors[]` | **一人一条** `<meta>`，不能合并成逗号串 |
| `citation_publication_date` | `year` | 只有年份，schema 未记月份 |
| `citation_journal_title` | `venue` | 仅 `type: journal` |
| `citation_conference_title` | `venue` | 仅 `type: conference`（字段名与期刊不同，写错抓取器整条忽略） |
| `citation_book_title` / `citation_publisher` | `venue` | 仅 `type: book` |
| `citation_publisher` | `venue` | 仅 `type: report` |
| `citation_volume` / `citation_issue` | 同名字段 | 有值才输出 |
| `citation_firstpage` / `citation_lastpage` | `pages` | 按连字符拆分；单页只出 firstpage |
| `citation_doi` | `doi` | |
| `citation_abstract` | 正文 | |
| `citation_pdf_url` | `pdf` | 转成绝对 URL，相对路径抓取器不认 |
| `citation_language` | 固定 `zh` | |

**引用条目生成（GB/T 7714-2015）**：

中文期刊投稿与学位论文的**强制**格式。BibTeX 只服务 LaTeX 用户，覆盖不了这批人。

| 类型 | 标识码 | 条目格式 |
|---|---|---|
| `journal` | `[J]` | `作者. 题名[J]. 刊名, 年, 卷(期): 起止页.` |
| `conference` | `[C]` | `作者. 题名[C]. 会议名, 年: 起止页.` |
| `book` | `[M]` | `作者. 书名[M]. 出版者, 年.` |
| `report` | `[R]` | `作者. 题名[R]. 出版者, 年.` |
| `patent` | `[P]` | `作者. 题名[P]. 年.`（schema 无专利号与日期字段，只能给最小条目） |

- 卷 / 期 / 页码**全部可选**，缺失时逐级降级（`22(6)` → `22` → `(6)` → 无），不留空占位符；
- **补数据才能得到完整条目** —— 内容侧未填 `volume` / `issue` / `pages` 时，条目会缺卷期页码。

**载体名语言分流（`formatVenue()`）**：含 CJK 一律用《》且 `not-italic`，拉丁用斜体。
中文出版体例用书名号；且 `Noto Serif SC` / `Noto Sans SC` **没有真斜体**，浏览器会合成机械倾斜，
既不合体例也难看。三处渲染（列表项 / 筛选器 / 详情页）必须共用这一个函数。

**BibTeX 规格（`src/lib/bibtex.ts`）**：

| 内容类型 | BibTeX 条目类型 |
|---|---|
| `journal` | `article` |
| `conference` | `inproceedings` |
| `book` | `book` |
| `report` | `techreport` |
| `patent` | `misc` |

- **引用键生成**：`<第一作者姓><年份><标题首个英文词>`，全部小写并剥离非字母数字。
  中文作者名无空格，`split(/\s+/).pop()` 会取到空串 —— 必须回退为「首字」；否则全部条目的键会塌缩成同一个 `<年份>`。
- 复制按钮使用 `navigator.clipboard`，失败时给出「请手动选择并复制」提示；
- 复制结果通过 `aria-live="polite"` 状态区播报，**不依赖视觉提示**；
- 两种格式的按钮共用 `data-copy-cite`，各自从所属 `<details>` 取 `data-cite-text`；
- 每条成果的引用键**必须唯一**（当前 10/10 通过）。

**结构化数据**：`ScholarlyArticle`（`headline` / `author` / `datePublished` / `isPartOf`），由 `JsonLd.astro` 以 `@graph` 输出。

> **已知缺失**：`publishedAt` 不再由 `new Date(year, 0, 1)` 伪造 —— 那会把 1 月 1 日当成真实发表日期。
> 现在只输出年份。若需精确日期，需在 schema 增加发布日期字段。

### 4.11.2 专题专栏 `/topics` 与 `/topics/:slug` ★ 横向聚合层

**定位**：成果 / 新闻 / 活动 / 项目都是「纵向」列表，专题是唯一把它们按主题串起来的横向维度。
没有这一层，门户就只是几张列表的堆叠。

**`/topics` 索引**：`portal-card` 网格，每张卡显示角标、标题、一句话说明，以及「含 N 项相关内容」计数。

**`/topics/:slug` 详情**：PageHero → 封面（有 `image` 用真实图，否则 `CoverImage` 回落抽象图形）→ 正文 →
专题成果 / 相关动态 / 相关活动 / 支撑项目 → 右栏（负责人、参与成员、相关方向、关键词）→ 上下专题。

**聚合规则（唯一依据是 `keywords`）**：

| 目标 | 匹配方式 |
|---|---|
| 成果 / 新闻 | 条目的 `tags` 与专题 `keywords` 有交集 |
| 活动 / 项目 | 这两个集合**没有 tags**，按关键词是否出现在 `title` 或 `summary` 中 |
| 参与成员 | 由「命中成果的作者 ∪ 命中项目的成员 ∪ 负责人」反推，**不靠猜** |
| 相关方向 | `research.keywords` 与专题关键词有交集，或关键词出现在方向标题中 |

> ⚠️ **关键词必须取自其他集合真实使用的词。** 本项目踩过：专题写的是「公共数据开放」，
> 而项目 `public-data-pricing` 与活动 `2026-10-pricing-seminar` 标题里用的是「公共数据授权运营」，
> 结果两者都没被聚合进来。同理「可解释性」匹配不到「可解释决策」，需要补一个更短的「可解释」。
> **新增专题后务必确认聚合结果非空** —— 各区块是条件渲染，匹配不到会整块消失，静态审计不会报错，只会静默变空。

**区块缺失是合法的**：并非每个专题都有新闻或活动。条件渲染即可，**不要渲染空标题**。

**导航**：专题是一级导航项，但**保持为纯链接**（不做 Mega Menu）——
条目由集合驱动，在导航里写死 slug 会让「新增专题」必须改代码，违背内容可维护性。全部专题由 `/topics` 索引页承载。

#### 4.17.1 富文本编辑器（`admin/src/components/MarkdownEditor.tsx`）

**设计前提**：正文最终以 **Markdown 源码**写入 `src/content/**/*.mdx`，Markdown 是**唯一真源**。刻意不做 HTML ↔ Markdown 双向转换的所见即所得——对已有的 MDX 内容是有损的。富文本体验由「工具栏 + 实时预览」提供。

| 项 | 说明 |
|---|---|
| 工具栏 | 二级标题 / 三级标题 / 粗体 / 斜体 / 删除线 / 无序列表 / 有序列表 / 引用 / 代码块 / 分割线 / 链接 / **插入图片**（12 项） |
| 选区语义 | 有选区就包裹或转换，无选区插入占位符并选中；多行选区逐行处理；已加标记再点一次取消 |
| 快捷键 | `Ctrl/⌘+B` 粗体、`Ctrl/⌘+I` 斜体、`Ctrl/⌘+K` 链接；列表内 `Tab` / `Shift+Tab` 缩进 |
| 预览 | 右侧分栏实时渲染（窄屏转到下方），**不切 Tab**，边写边看；底部显示字数与行数 |
| 预览语法 | 标题、粗/斜/删除线、行内代码、围栏代码块、多级嵌套列表、引用、链接、**图片**、表格、分割线、段落 |
| 无障碍 | 纯图标按钮必须带 `aria-label`（MUI `Tooltip` 只给 `aria-describedby`，不提供可访问名称） |

**安全**：预览渲染**先整体转义再套标签**；链接只放行安全协议，拦截 `javascript:` / `vbscript:` / `file:` 与非图片的 `data:`。**不引入 Markdown 解析库**（`marked` / `markdown-it` / `remark` 一律不用）——正文用不到完整 CommonMark，且不能给这个零依赖后台增加体积。

#### 4.17.2 图片资源库（`POST|GET|DELETE /api/assets`）

- **存储**：`<仓库根>/public/images/`，Astro 把 `public/` 映射到站点根，因此引用路径就是 `/images/<name>`。上传后需点「发布站点」重新构建才会出现在站点里。
  - **`public/` 下的东西会原样发布**，所以这个目录里**只放图片**，不要放说明文档或 `.gitkeep` 之类的占位文件（曾经放过 `README.md`，结果它出现在了线上 `/images/README.md`）。
  - 目录由后台的 `ensureAssetsDir()` **按需创建**，仓库里可以不保留空目录；目录不存在时 `GET /api/assets` 返回空列表而不是报错。
- **传输**：`POST /api/assets` 收 **JSON**（`{ name, type, dataBase64 }`），**不引入 multipart 解析依赖，也不手写 multipart 解析器**——本地 CMS 场景，base64 足够。
- **校验链**：MIME 白名单（`png/jpeg/gif/webp`，**拒绝 SVG**，可内嵌脚本有 XSS 风险）→ base64 解码 → 体积 ≤ 5 MB → **魔数校验**（`89 50 4E 47` / `FF D8 FF` / `GIF8` / `RIFF…WEBP`，防止改扩展名骗过检查）→ 文件名净化（去掉分隔符与 `..` 防目录穿越、中文转 ASCII、按 MIME **强制修正扩展名**）→ 重名追加 `-1` / `-2`。
- **删除**：同样净化文件名，且只允许删 `public/images/` 下的一级文件。
- **前端**（`AssetPicker.tsx`）：缩略图网格 + 点击选择文件 + **拖拽上传**（逐个显示「正在上传 x/y」，后端错误原文展示）+ 点击插入 `![name](/images/xxx.png)` + 二次确认删除。
