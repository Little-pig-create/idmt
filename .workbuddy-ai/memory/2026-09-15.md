## 抓到一个「正文静默不渲染」的真 bug（成果详情页 10 页全中）

用户诉求：「继续完善相关页面」。查详情页现状时发现。

### 症状

`src/pages/publications/[slug].astro` 第 119 行：

```astro
{data.body ? <Content /> : (<p class="text-ink-tertiary">（暂无摘要）</p>)}
```

而第 20 行是 `const data = item.data;`。**正文在 `item.body`，不在 `item.data.body`**
（`data` 只是解析后的 frontmatter）→ `data.body` **恒为 undefined** →
三元永远走 else，**10 个成果详情页全部显示「（暂无摘要）」，真正的摘要一次都没渲染过**。

### 取证（不是在脑子里推理）

- `dist/publications/data-property-contract/index.html` 里 `暂无摘要` 命中 1 次；
- 而源文件正文明明有内容：「将数据产权"三权分置"从政策表述转化为可签约的权利束…」。
- 即**产物里没有正文、有占位符** → 坐实。

### 修法

`data.body` → `item.body`（一行）。

**复验（改后）**：该页 `暂无摘要` 命中 **0** 次，`三权分置` 出现在产物里；
`dist/publications/*/index.html` 中仍显示「暂无摘要」的页面数 = **0**（10/10 恢复渲染）。

### 反向测试：确认是孤例，不是一类病的表面症状

写循环对 **7 种详情页**各取一条，抽正文前 6 字去对应产物页里 `grep -F`：

```
news / people / events / projects / research / topics / publications  → 全部 OK
```

结论：其余 6 种都是**无条件** `<Content />`，所以不会犯这个错；
`.body` 在整个 src/ 里也只有这一处用法。**修一处即收口。**

build 51 页 · audit ✅ · taste ✅ · contrast ✅ 22/22 · docs:tokens ✅ · smoke 30/30。

## 顺带查清：新闻详情页为什么没有「相关」区块

7 种详情页里，news 是**唯一一个零相关内容**的（只有上下篇）。想补，但先验证数据撑不撑得住：

1. **按 tag 找相关新闻 → 恒空**。6 条 news 的 tag 两两不重复
   （招生 / 荣誉 / 学术成果 / 合作 / 数据要素 / 会议 / 主旨报告 / 学术活动 / 科研 / 项目立项），
   **没有任何两条新闻共享 tag**。做出来就是永不触发的假功能。
2. **按 tag ∩ 专题关键词 → 只中 1 条**（`数据要素` → data-authorization）。
3. **退一步用正文文本匹配**（专题关键词出现在标题/摘要里，即 topics 对 events/projects 的 `textual()` 办法）：
   命中 3/6 —— cooperation（公共数据授权运营、定价）、forum（数字治理）、
   policy-data-bureau-grant（数据局）。
   注意 `2026-data-governance-forum` **不中**：正文是「**数据**治理」，关键词是「**数字**治理」，
   一字之差匹配不上 —— 中文近义词不能靠子串硬套。

**结论：新闻「相关专题」最多覆盖 3/6，另 3 条会恒空。**
按本项目「不做永不触发的假检查」的原则，**没有硬上**，留给用户决定是否接受半覆盖、
或先补数据（给新闻打上真正可聚合的 tag）。

## 把这次事故固化为门禁：SCHEMA-REF-001（`npm run schema:refs`）

**为什么必须做门禁**：上面那个 `data.body` bug，audit / taste / smoke **全都发现不了** ——
页面照样返回 200、照样有标题和元数据，只是正文被换成占位符。
这类「静默降级」只能靠静态引用检查抓。

脚本 `scripts/schema-refs.mjs`（零依赖）：
1. 正则解析 `src/content.config.ts`，抽出 8 个集合的字段并集（42 个字段）；
2. 扫 `src/**/*.{astro,tsx,ts}` 里的 `.data.X` 与裸 `data.X`（`const data = item.data` 这种写法也得抓）；
3. 不在并集里 → 报警。其中 `body`/`id`/`slug` 等**条目级属性**只在明确写成 `data.body` 时才报
   （`item.body` 是合法的，脚本不去推断变量归属）。

**只做「并集判存」，不做「哪个集合该有哪些字段」的精确归属** ——
后者要跨文件推断变量对应的集合，成本高且易误报；而拼错字段名这类真实事故，并集判存足够全部抓住。

**反向测试（两个分支都验了，跑完已还原）**：
- 把 `item.body` 改回 `data.body` → exit 1，报「条目级属性，只能写 `item.body`」；
- 注入 `data.auther` → exit 1，报「schema 中不存在该字段」；
- 还原后 exit 0，`item.body` 在位、注入痕迹已清。

已接入 `package.json`。**门禁链更新为**：
`build → audit → taste → contrast → docs:tokens → schema:refs → smoke`

全链复验：build 51 页 · audit ✅ · taste ✅ · contrast ✅ 22/22 · docs:tokens ✅ ·
**schema:refs ✅** · smoke 30/30。
